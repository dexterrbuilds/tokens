title: Execution
description: Venue deep links and pre-trade depth evaluation for buy/sell flows.

All endpoints on this page are Platform API endpoints authenticated with `x-api-key` and
require the `execution:read` scope (granted to all keys by default).

## `GET /v2/execution/links`

Deep links to swap venues for buying a token. Use it to power a "Buy" call-to-action:
pick the venues you want to show, render them in any order, and treat `primary` as our
recommendation. Links carry no quote — the venue computes the live price when your user
lands there.

The contract is kind-based: today every link has `kind: "swap"`; future kinds (perps,
pools) will be added under the same shape. `meta.kinds` advertises what the deployment
supports.

- **Scope**: `execution:read`
- **Query params**:
  - `mint` — buy-side Solana mint. Exactly one of `mint` / `assetId` is required.
  - `assetId` — canonical asset id or alias (e.g. `bitcoin`); resolves to the asset's
    primary Solana variant. Unknown ids return `404`.
  - `sellMint` (optional) — overrides the sell side. Defaults to SOL, or USDC when buying SOL.
  - `venues` (optional) — comma-separated venue ids to include. Valid ids: `titan`,
    `jupiter`, `dflow`, `sunrise`, `omfg`, `kamino`, `orca`, `raydium`, `byreal`.
    Unknown ids return `400` listing the valid set.
  - `kinds` (optional) — comma-separated link kinds. Currently only `swap`.
  - `amount` (optional) — sell-side amount as a positive decimal string. Reserved:
    currently accepted but not appended to any venue URL.

```ts
interface ExecutionLinksResponse {
    buyMint: string;
    sellMint: string | null;
    asset: { assetId: string; symbol: string | null } | null; // registry match for the buy mint
    primary: string | null; // our venue recommendation; null when filtered out
    links: Array<{
        id: string; // venue id, e.g. "titan"
        name: string; // display name, e.g. "Titan"
        kind: 'swap';
        venueType: 'aggregator' | 'dex';
        url: string;
        iconUrl: string | null;
    }>;
    meta: { kinds: string[] }; // link kinds this deployment supports
}
```

Some venues drop out per pair instead of erroring: Sunrise (which resolves tokens by
mint but lists a limited asset set) is omitted when the mint has no registry symbol,
and same-mint pairs are omitted where a venue can't express them.

```bash
curl -H "x-api-key: $API_KEY" \
  "https://api.tokens.xyz/v2/execution/links?assetId=bitcoin&venues=titan,jupiter,orca"
```

## `GET /v2/execution/evaluate`

Evaluate a hypothetical buy or sell of a canonical asset against **current sampled
on-chain depth**. This is an evaluation surface, not an order router — it never routes
or executes anything. Ask it "how good is a $1M buy of bitcoin on Solana right now?" and
it answers per variant mint, with a grade.

### Why evaluate before you trade

- **Pre-trade guardrails.** Gate or warn on a Buy CTA when the user's size grades `poor`
  or `avoid`. HYPE absorbs $1M at 140bps but $5M costs ~7,000bps (you'd receive ~30% of
  your input) — this tells you which side of that cliff a user is on before they click.
- **Treasury / OTC sizing.** Find the largest clip that still grades `good`, or split an
  order across the sampled ladder instead of discovering slippage after the fill.
- **Variant selection at size.** The best mint changes with size: cbBTC beats wBTC at
  $1M and loses to it at $5M. Pick per trade, not per asset.

### Two modes

- **Without `amountUsd`** — the scorecard: each variant returns its sampled `ladder`
  (one entry per size rung) with a grade per rung. One cheap call, ideal on page load.
- **With `amountUsd`** — adds `estimatedImpactBps`, `estimatedOutUsd`, `sizeAwareScore`,
  and `executionGrade` interpolated (log-linear) at your exact size.

- **Scope**: `execution:read`
- **Query params**:
  - `asset` (required) — canonical asset id, alias, or Solana mint (e.g. `bitcoin`).
  - `amountUsd` (optional) — intended trade size in USD, clamped to `[1, 50000000]`.
  - `side` (optional) — `buy` (default) or `sell`.
  - `sample` (optional) — `missing` asks the API to sample uncovered mints on demand
    before answering (read-through warm: the result is persisted, so only the first
    caller waits). Bounded server-side: ≤4 mints per request, and mints sampled within
    the last 30 minutes are skipped. Adds a few seconds when it fires.
  - `quotes` (optional) — `sampled` (default) or `live`. With `live` + `amountUsd`, impact
    is measured from two quotes fetched at request time (a $10K baseline and your size)
    instead of interpolating stored curves. Adds upstream latency (~2-3s for multi-variant
    assets); variants whose live quote fails fall back to sampled with a
    `live_quote_unavailable` reason. `meta.quoteMode` reports what was actually used.

### Grades

`impactBps` maps to a grade via inclusive upper bounds. The scale is ordered
best-to-worst, so you can rank or threshold on it:

| Grade | Impact (bps) | Read as |
| --- | --- | --- |
| `excellent` | ≤ 10 | negligible cost |
| `good` | ≤ 50 | normal for size |
| `fair` | ≤ 150 | noticeable, still tradeable |
| `poor` | ≤ 500 | expensive — consider splitting |
| `avoid` | > 500 | not enough depth at this size |

`meta.gradingVersion` identifies the thresholds (`impact-grade-v1`). It changes whenever
the boundaries or the grade set change, so pin behavior on it rather than hardcoding
numbers.

```ts
interface ExecutionEvaluateResponse {
    asset: { assetId: string; name: string | null; symbol: string | null; category: string | null };
    side: 'buy' | 'sell';
    amountUsd: number | null;
    primary: { mint: string; variantId: string; reason: string } | null;
    variants: Array<{
        rank: number; // 1-based
        mint: string;
        variantId: string;
        kind: string; // native | wrapped | bridged | spot | lst | ...
        issuer: string | null;
        trustTier: string;
        symbol: string | null;
        name: string | null;
        liquidityUsd: number | null;
        volume24hUSD: number | null;
        executionScore: number | null; // 0-100 fill-quality score
        feeBps: number | null;
        isFillQualityEligible: boolean;
        // Sampled evaluation points; null when this variant has no fresh depth sample.
        ladder: Array<{ sizeUsd: number; impactBps: number; grade: string }> | null;
        // The four fields below require `amountUsd`.
        estimatedImpactBps: number | null;
        estimatedOutUsd: number | null;
        sizeAwareScore: number | null;
        executionGrade: string | null; // grade at amountUsd
        depthAsOf: number | null; // unix seconds of the depth sample
        reasons: string[]; // e.g. ["liquidity"], ["only_candidate", "depth_unavailable"]
    }>;
    meta: {
        asOf: number; // unix seconds
        scoringVersion: string;
        sizeAwareScoringVersion: string | null; // non-null only once depth influences ordering
        gradingVersion: string; // e.g. "impact-grade-v1"
        quoteMode: 'sampled' | 'live'; // whether any live quote informed this response
        strategy: 'execution_quality' | 'size_aware';
        sizeLadderUsd: number[] | null; // the sampled rungs, when any variant has depth
        depthSource: string | null; // e.g. "titan"
        depthCoverage: { withCurves: number; total: number };
    };
}
```

Variants without a fresh depth sample carry `depth_unavailable` in `reasons` and a null
`ladder`; samples older than 6h are treated as absent. A variant that was sampled and had
**no route at any size** carries `no_route` with an empty `ladder` — the strongest avoid
signal, distinct from "not sampled yet". An `amountUsd` beyond the largest
sampled rung is clamped and flagged with `beyond_sampled_depth`. Size-aware fields are
informational — they do not reorder `variants` while `meta.sizeAwareScoringVersion` is
null. Single-variant assets return one entry with `primary.reason: "only_candidate"`;
assets with no Solana variants return an empty `variants` array and `primary: null`.
Unknown assets return `404`.

```bash
# Scorecard: graded ladder per variant
curl -H "x-api-key: $API_KEY" \
  "https://api.tokens.xyz/v2/execution/evaluate?asset=bitcoin"

# Evaluate a specific size (sampled curves)
curl -H "x-api-key: $API_KEY" \
  "https://api.tokens.xyz/v2/execution/evaluate?asset=bitcoin&amountUsd=1000000"

# Same, but with quotes fetched at request time
curl -H "x-api-key: $API_KEY" \
  "https://api.tokens.xyz/v2/execution/evaluate?asset=bitcoin&amountUsd=1000000&quotes=live"
```
